Communication Technologies for LLN

We will consider MAC layer for this networks (LLN)

Low Duty-Cycle MAC Protocols

Part of the duty-cycling for energy saving (previous page)

  1. Time-Slotted Access Protocols → effective reduction of power consuption, assigning each time slots to a specific node (TDMA)
  1. Contention-based MAC (CSMA) → also called random access
    • High energy expenditure (over-hearing, collisions)
    • No need for synchronization between nodes
    • High scalability → no maximum number of nodes in the network (increase the probability of collisions and then energy consumption)
      • Good when the number of nodes are not that high
  1. Hybrid Scheme → both TDMA + CSMA, switching based on contention
  1. Polling-Based Access Protocols → master-slave approach
    • Slaves are polled by the master node, according to some schedule, then they can communicate
    • effectively reduce the power consuption
    • Synchronization is required, because nodes needs to know when to wake-up

Time Slotted access

Each node is active only during its own slot(s), and can sleep during the other slots. Each node gets one or more fixed-length slots in each round → same in every frame

  • Effective power reduction, but needs precise syncronization
  • No medium contemption → more reliability (less energy consuption)
  • Bounded and Predictable Latency: each node accesses the same slot(s) in every frame. You can calculate the max time the node has to wait before to send the packet
  • Join and leave of nodes may cause slot re-allocation → unused slots go idle → limited flexibility
  • Vulnerability to Selective Jamming attacks: for example you can try to transmit simultaneously during a specific slot → confused with communication error

Superframe reserved slot used for:

  1. Coordinator to node communication (SYNCH, slot allocation,…)
  1. Node to Coordinator communication (slot request, …)

Example protocol: Time Division Multiple Access (TDMA)

Random-Based Access

Communication approach where devices transmit data without a predefined schedule or slot allocation.

  • Asyncronous → no need for syncronization
  • Nodes wake up only when they need to transmit or receive data
  • A large number of nodes can cause a large number of collisions and retransmissions
  • A topology change do not require any re-configuration or schedule update notification

IEEE 802.15.4

One of the most popular technologies used for low power communication in Personal Area Networks (PANs)

  • This standard covers only physical and data link layer
  • It is also known as Zigbee (network layer and upper layers), in reality they are complementary (IEEE 802.15.4 is data link and physical layers)

IEEE 802.15.4 Topologies

  • In star network I cannot have peer-to-peer communication since they need to communicate first with PAN coordinator

Channels

We have 27 channels, with different frequencies → they provide different throughput

  • The 11-26 can be used everywhere (no geografic limitation) and provide higher bitrates → they are the most used channels
  • Channels help avoid collisions, but the standard typically operates on only one channel at a time

Adresses

PAN Address → Identifies the PAN within a certain geographic area

  • Allows the communication between different PANs
  • 16 bits (Broadcast PAN Address: 0xFFFF)

Device Address → Identifies the device within a PAN

  • Extended Address: 64 bits MAC address → not sustainable for IoT (just 20B for adressing: receiver, sender, PAN receiver, PAN sender adresses)
    • Most significant 24 bits assigned by IEEE (OUI), least significant 40 bits assigned by manufacturer
  • Reduced Address: 16 bits
    • Negotiated with the PAN coordinator
    • Can replace the extended address in all communications
    • Broadcast address: 0xFFFF

Frame Format (PHY)

102 bytes maximum MAC payload, but with reduce adress I can use 114 bytes

  1. Frame Control (2 bytes): Contains information about the frame type, addressing mode, security settings, and other control information.
  1. Sequence Number (1 byte): Helps in tracking frames and managing duplicate frames in communication.
  1. Frame Check Sequence (FCS) (2 bytes): Used for error detection, ensuring data integrity → called MAC footer

  1. Synchronization Header in phy layer: Helps synchronize the receiver with the incoming data transmission.

There are two different modes for IEEE 802.15.4

  1. Beacon mode → periodical broadcasted msg (beacon) that coordinate and syncronize the network (sent from PAN coordinator)
    • The time between two consecutive beacon is called beacon interval
    • The Superframe structure is defined within the Beacon Interval and consists of an active period (for data transmission) and an optional inactive period (for power saving).
  1. Non Beacon mode → no beacon trasmitted
    • The protocol used is unslotted CSMA-CA (random access protocol)

1. Beacon-Enabled (BE) Mode

We refer to the star topology: the PAN coordinator is responsible to send periodic Beacon (the period is a parameter that can be changed).

The time is divided into Backoff slots (or periods), which represent the smallest unit of time, they are aggregated under communications slots

  • All node activities, such as starting the transmission of a frame, can only begin at the beginning of a Backoff slot
  • If a node successfully sends its request to transmit in a GTS, it can only transmit in the next
    Beacon Interval. This is because the response from the coordinator node will arrive within the next Beacon.

Space between two beacons is called super frame → there is an active part where nodes are active (communication is possible) and an inactive part (no communication possible)

  • Sleep and wake up scheme → Devices use these beacons to wake up and communicate efficiently
  • Syncronization at beacon trasmission

Active period is divided into:

  1. Contention access period (CAP), during the CAP a slotted CSMA/CA algorithm is used for channel access
    • During this interval, nodes can request to be assigned a GTS
    • If a node sends the request, it can only transmit in the next Beacon Interval. This is because the response from the coordinator node will arrive within the next Beacon.
  1. Contention free period (CFP), communication occurs in a TDMA style by using a number of Guaranteed Time Slots (GTS), pre-assigned to individual nodes (for the current superframe)
    • 16 communication slots of fixed length, at most 7 given to CFP

CSMA-CA Algorithm

  • CW: Contention Window → counter that tracks the number of backoff periods that need to be clear of channel activity before transmission can begin → two consecutive CCA (clear channel assesment)
    • Otherwise I could have two that sense the medium free and start communicating
  • BE: Backoff Exponent - Determines the range of the random backoff period. The initial value is typically set to 3
    • aMaxBE: The maximum value that BE can reach
  • NB: Number of Backoffs - Tracks how many times the device has backed off due to a busy channel
    • macMaxCSMABackoffs: Maximum number of allowed backoff attempts before declaring failure.
  • Backoff period: time during which a device waits before attempting to access the communication channel
    • double at each attempt the maximum possible interval
    • randomization is foundamental because it avoid multiple devices to start trasmission together → uniform sampled
    • BP∈[0,320⋅(2BE−1) µs]BP \in [0, 320·(2^{BE}-1)\space µs]BP∈[0,320⋅(2BE−1) µs]﻿
    • The starting time of the backoff timer is aligned with the beginning of the next backoff slot
    • If the backoff time is larger than the residual CAP duration, the backoff timer is stopped at the end of the CAP and resumed at the beginning of the next superframe

At success I can trasmit my msg → may not be delivered correctly

  • ACK is optional, can be enabled or disable depending on application reliability requirements
  • Retransmission if ACK not correctly received within the timeout → re-initialize the parameters of the algorithm from scratch
  • Only a maximum number of retransmissions allowed
  • Higher energy consuption

The packet may be discarded for two reasons:

  1. max number of attempts of communication medium (the data may become useless after some time)
  1. max number of retrasmission without ack (eg. 3) → may or may not be enabled the retrasmission

  • The first CCA of B fails (because it last a small amount of time and A start trasmitting) → The superframe interval finished before a new CCA → timer is frozen
  • Then B perform the two CCA and trasmits
    • Note that every operation must start at precise time, not immediatly

Security

  1. Unsecured mode
  1. ACL Mode (access control list) → any node has an ACL specifying nodes that are authorized to perform specific actions
  1. Secured Mode → based on AES with 128-bit key. Consist of ACL and:
    1. Replay attack protection → when an attacker intercepts and resends a valid message to trick the system into performing an unintended action (eg. authentication)
    1. Message integrity → ensures that a message has not been altered in transit, either accidentally or maliciously
    1. Confidentiality → ensures that only authorized entities can read the message, preventing unauthorized access

Problems with the Beacon Mode

  1. Power Management disabled → meaning that there is no inactive part
    • Not much collisions since they are spreaded over all the superframe
  1. Power Management enabled + Poisson Traffic → the packets generated during the sleeping time are deferred to the beginning of the next Active Period
    • Therefore, channel access attempts tend to become synchronized
  1. Power Management enabled + Periodic Traffic → the msgs are generated just before the beacon
    • maximum competitions since every node has something to trasmit

Drammatic decrease of the delivery ratio → many packets are not received correctly by the destination

  • even with ACK since we cannot continously send them (two max threshold)

It’s not a problem of the algorithm per se. In fact in WIFI we got perfect delivery ratios

Simulation on Parameters

Simulation on worst conditions (in 15 sensor nodes):

  1. Periodic Traffic
  1. Power Management ON
  1. ACK ON

  • The total energy increase because more messages are sent
  • But the energy per packet decreases → because if a packet is not received, then the energy is wasted
  • Even if we increase the number of backoff stages to very high values (like 10) the delivery ratio is under 80%

  • Initial backoff periods are larger → less collisions

Result of the analysis

  1. The MAC unreliability problem is mainly due to the CSMA/CA algorithm (contemption)
  1. The periodic beacon synchronizes channel accesses thus maximizing contention
  1. The problem is exacerbated by the default MAC parameter values
    • Not appropriate for Wireless Sensor Networks (WSNs) operating in BE mode

  1. DSP (Default Parameter Set) → suggested values by the standard
  1. SPS (Standard Parameter Set) → standard compliant max values
  1. NPS (Non-Standard Parameter Set) → larger values

  • The cost to pay is the higher latency
  • Third Graph → percentage of packets that can be delivered given a deadline
    • when the deadline is less than or equal to 100 ms, the fraction of packets delivered on time is below 20%, irrespective of the parameter set.

  • High speed PAN, instead the 802.15.4 for low speed PAN
  • Short range, but power angry so it wasn’t suitable for IoT → BLE (bluetooth low energy)

Bluetooth 4.0, introduced in 2010, prioritized low energy consumption over raw speed (1Mbps).

  • Bluetooth 4.0 also introduced dual-mode capabilities, allowing devices to support both the energy-efficient BLE protocol and the traditional Bluetooth protocol

In BLE there are 40 channels available, but three of them cannot be used for data exchange, but only for beaconing

It allows two modes of communication:

  1. Advertise Mode: involves broadcast communication where we have two types of nodes.
    • Advertisers are Beacon devices that send messages
    • Then we have observer nodes that wait to receive the messages

LoRaWAN

LoRaWAN end devices are optimized to operate in low power mode and can last up to 10 years on a single coin cell battery.

  • LoRaWAN gateways can transmit and receive signals over a distance of over 10 kilometers in rural areas and up to 3 kilometers in dense urban areas
  • A LoRa end device can be located if at least three gateways pick up its signal, without GPS
  • Operates on the unlincesed bandwidth
  • It can handle millions of devices
  • Ensure AES-128 bit encyption
  • Firmware updates over the air

It can trasmit to more Concentrators (if they are in range), then more probable to arrive correctly to the server

  • Higher bitrate → lower maximum distance

Class A devices

Must be implemented on all the devices using LoRa, other classes are just extensions.

  • Devices in this class have really a low power consuption → can operate with battery
  • Class A devices have high downlink latency
    • They require sending an uplink (message) to receive a downlink (response)

A Class A device can send an uplink message at any time. Once the uplink transmission is completed, the device opens two short receive windows for receiving downlink messages from the network

After sending the message, switch the radio from send to receive mode (in order to achive the ack)

  • If not received in the first attempt, try a second, then sleep.
  • one direction communication

Class B devices

Class B devices extend Class A capabilities (lower latency for downlinks) by periodically opening receive windows called ping slots to receive downlink messages. The network broadcasts a beacon periodically for syncronization

  • often battery powered → maybe with harvesting systems
  • Class B mode can be used in devices that require medium-level critical actuation, such as utility meters (water meters, electrical meters)
  • beacon synch clock of the devices

Class C devices

Class C devices extend Class A capabilities by keeping the receive windows open unless transmitting an uplink

In this case two different frequencies are used → dedicated channel to reception, then ack

  • They consume more power, due to the need for opening continuous receive slots
  • Not powered by batteries, but from electrical grids
  • Lowest latency because it could receive almost immediatly
