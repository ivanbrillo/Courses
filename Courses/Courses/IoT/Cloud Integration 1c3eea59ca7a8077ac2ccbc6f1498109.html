Cloud Integration

Challenge to conntect constrained devices to the network

Vertical Systems

  • Designed to serve one single purpose (eg. smart termostat works only with the application of that vendor) → it’s not open
  • Inefficient: each device is dedicated to a single application
  • Operating in isolation: no (or very limited) cooperation

Business Application normally runs in the Cloud

There are some integration, with devices called aggregator (like Alexa), but there is not a direct conntection between the two, because the aggregator doesn’t talk to the device directly but with the business application

  • Alexa integrate everything at Business Application

Horizontal Approach

  • Converged infrastructure → unified sensing and actuating infrastructure
  • Support for multiple applications (from different vedors) → they are open
  • Can be used by any application in an open manner

Eg. Intrusion application that uses also the termostat sensors that was designed to understand if the owner is at home

  • Not buy the vertical from the market, but the sensors

We need a standardization process

  • The internet is an example of this (HTTP)

We have an external agency that is defining the protocols for IoT based on IPv6

  • Set of IPv6-based solutions have been defined by IETF (6LowPAN, ROLL, COAP)

Direct Cloud Integration

Almost all Cloud providers (AWS, Azure, …) provide IoT support. Service capable to:

  1. Receive sensors information
  1. Skeleton to write the UI
  1. Skeleton to be deployed on IoT devices to communicate with the cloud (the broker in MQTT)

They all adopt a common protocol called MQTT

MQTT

MQTT (Message Queuing Telemetry Transport) is a publish/subscribe messaging protocol designed for lightweight M2M (machine to machine) communications

  • MQTT has a client/server model, where every sensor is a client (that produce or consume data) and connects to a server, known as a broker, over TCP
  • Borned before IoT

Every message is published to an address, known as a topic (meta-information that specify the content of the message, usually a string “temp”)

  • Clients have to subscribe to topics of interest, if needed they can subscribe to multiple topics

Sensors (MQTT Clients) publish on pre-defined topics

  • Every vendors, deploy a MQTT broker

Other sensors or other modules (DB, UI, ML models, …) of the cloud platform subscribe to the topics

Rapid deployment is the main goal

  • Things connect through a local WiFi network, which is usually pre-existing (no new network equipment is required) → in every home, industry and city
  • An initial skeleton of the code to program the sensors is usually provided for a set of popular boards by any cloud provider

Advantages

  1. Rapid (skeletons) and simple (everyone has wifi) deployment for IoT vendors
  1. It does not require the installation of a new infrastructure
  1. It scales with Cloud infrastructure (since the application is in Cloud)

Drawbacks

  1. Cloud is always involved
    • Low latency applications are not supported
    • Needs persistent connectivity → in network outage the system will not work even though the two devices are just communicating between each other
    • Direct M2M interactions are not possible, needs to go from could (broker) and come back
  1. WiFi was not designed with IoT in mind
    • Energy consuming (battery devices are not supported)
    • The coverage is equal to the radious of Access Point/Router

The protocols for power constrained devices are the one introduced in earlier lessons

Applications that are not supported

They are not supported since they need:

  1. low latency
  1. reliability (when network outages they do not work)

Manufacturing Inspection

Detect defects of products by analyzing images of goods

  • Cameras are installed directly on the production line
  • Images are analyzed through DL techniques to identify defects or issues
  • If a defect is identified, the item is removed from production

If the delay of communication is above a treshold, the good may be gone past the production checkpoint and cannot be removed

Autonomus Robot

Unmanned logistics, e.g. upload and deliver cargos in the warehouse

  • Manage and support autonomous logistic systems, e.g. drones or mobile robots
  • Analyze data in real-time and manage the autonomous systems, e.g. by modifying the flight plan of drones
  • Data is analyzed though AI and ML techniques

Augmented Reality

Augmented reality to support workers, e.g. during inspection or regular production processes

  • Analyze the images in real time to enrich the them with supporting information

Fog Computing

It looks like a good idea to come back at the old pre-cloud approach, where data is collected and analyzed locally

  • Low latency
  • Loss of connectivity still ensure communcication

We do not want to remove the cloud completly because it’s still needed for the applications that do not require high reliability and low latency

  • It brings additional advantages

In order to solve these issues, recently, an extended Cloud architecture is adopted to introduce an additional layer, the Fog Layer

  • It is composed of nodes installed in proximity of sensor, this layer allows the execution of a local application logic and data analysis

Keep the majority of computing power in the cloud (since cheaper, scalable …) but some put it inside the fog layer in order to provide high reliability and low latency

  • multiple layer of computations
  • Fog computing is an extension of classic cloud paradigm

An application can be moved from the cloud to the fog or vice-versa since the environment is the same thanks to the isolation provided by lightweighted virtualization

Advantages

  1. the applications that are RT can be deployed on the fog layers
    • low latency, reliability, resiliency to network outages, privacy (data is not sent online)
  1. Advantages of cloud computing are preserved

Fog Hardware

Enriched hardware with ad-hoc peripherals for parallel computing, graphic support and AI/ML hardware support

  • directly integrated with the cloud

Virtualization Techniques

Fog computing systems adopt the same technologies adopted in Cloud computing systems: Virtualization techniques

  • Virtualization allows to develop applications that abstract from specific hardware and system components, thus ensuring compatibility and rapid deployment
  • Fog systems adopt lightweight virtualization technologies in order to meet the reduced capabilities (from the cloud)

Gateway - Fog node

It can:

  1. Execute some simple local application logic and data analysis that requires low-latency
  1. Implement protocol translation functionalities
    • It has also to implement security functionality to regulate access from outside networks

It enables the adoption of a wireless technology specifically designed for IoT:

  • Low-power
  • Large coverage through multi-hop

MQTT does not fit well in this architecture

  1. Where do we place the broker? One in the gateway and one in the cloud?
    • cloud → high latency
    • gateway → scalability issues (when high volume of data to be trasmitted to the broker)
    • Two broker is inefficent and present data syncronization problems
      • What happens if a sensor is of interest of two applications, one running in the cloud one in the gateway?

Web Of Things Approach

A Web of Things approach fits well in this architecture.

  • Each sensor provides an interface to expose their services (e.g. an information, a function) to applications.
  • The interface exposed by the devices is invoked directly by applications when needed.
    • The operations are performed in the same way, from the gateway or from the cloud.
    • IPv6 with its large addressing space will allow devices to be directly reachable.

Advantages

  1. Simple: a broker is not needed
  1. Energy Efficient: data is transferred only when needed (if no application consumes the data it is not transferred)
    • In the MQTT architecture, data was transferred from the sensor to the broker even though there was no subscriber
  1. Common interface: data retrieval or function invocation are performed in the same way on different hosts
    • Allows machine to machine interactions
  1. Better integration with the Web
