Limits of 802.15.4 CSMA/CA

  • no guarantee on end-to-end delay
  • limited communication reliability
  • no built-in frequency hopping technique → then high external interference since we are using low power communication
    • eg change frequency every time slot in bluetooth
    • multi-path fading
  • powered relay nodes

The MAC unreliability problem is mainly due to the CSMA/CA algorithm

  1. In BE mode the periodic beacon maximizes contention
  1. The problem is exacerbated by the default MAC parameter values
    1. not appropriate for WSN’s with power management enabled
    1. increasing parameters (higer reliability) comes with the cost of higher latency

Multi-Path Fading

WiFi has 11 channels, but the band is really crowded since it’s unlicensed

  • imagine having 802.15.4 over those frequency (where there is wifi, blutooth, …)
  • You cannot predict before in which freqency WiFi is communicating

Multi-Path Fading → signals will arrive to destination with different path (and different delays)

  • they can form constructive or destructive interference

Subsequent packets are sent at a different frequency → presudo-random hopping pattern

  • If a transmission fails, retransmission will happen on a different frequency
  • Increased security against selective Jamming attack

802.15.4 TSCH

Designed specifically for high reliability and low delay

  • Time Slotted Channel Hopping (TSCH)

Physical layer is the same, replace CSMA/CA that is not suited for these types of applications

Based on:

  1. Time-slotted access (in CSMA/CA is not devided in time slots, specially the non beacon)
    1. predictable and bounded latency
    1. guaranteed bandwidth (since assigned to a node, no contemption)
    1. no collision
    1. energy efficient (can be turned off during other slots)
  1. Multi-channel communication
    1. more nodes can communicate at the same timeslot, using different frequencies
    1. increased network capacity
  1. Channel Hopping
    1. Mitigates the effects of interference and multipath fading
    1. improves communication reliability

Time Slot Structure

Since nodes are not exactly synchronized, it’s necessary to introduce a delay before transmission, in order to avoid overlapping communication

  • difference between the nominal and actual start/end of communications
  • startup_time: after a certain period the node B become ready to receive a packet
  • After an additional guardtime the node A node can transmit it’s message (to ensure that the receiver is truly prepared to receive the packet)
  • After the transmission of the packet, there’s a certain period were both A and B switch their radio from Tx mode to Rx mode and vice-versa.
  • Once the node A is ready to receive the ack, but again there’s a guardtime that the node B must wait before transmit the ACK.
  • After the ACK there’s a stop time before the next time slot.

Channel offset uniquely identify a frequency channel

A link is defined as a pairwise assignment of directed communication between devices in a specific time slot, utilizing a particular channel offset

Using dedicated links, no collision can occur

  • determistic traffic

Using shared links there could be collision (if E, G will communicate together)

  • can be used if the communication is sporadic, unpredictable traffic

  • channel blacklisting, frequency hopping, pre scheduled timeslots, AES encryption
  • Self-organizing and self-healing mesh networking → under control of network manager (very centralized approach)

The policies for allocating cells is been created by an architecture called 6TiSCH

  • enable IPv6 connections

Different approaches for scheduling

  1. Static → predefined and cannot change
  1. Centralized → similar to wirelessHart, where there is a master that distribute the best shedule of different nodes
    • not good in all the environments
  1. Decentralized → calculated autonomously by nodes
    1. Collaborative → exchange information in order to create a schedule (typically suboptimal schedule, local optimum because it can rely only on local information)
      • not good in practice, is not very dynamic since they need to negotiate every time (consume bandwidth and takes time in critical application)
      • prone to security attacks from a malicious node
    1. Autonomous → slots are assigned without negotiation
  1. Hybrid → combining two or more scheduling approaches

Static Scheduling

Used only in the initial phase of the network, preconfigured

  • nodes learn it when they join the network

Minimal configuration → initial timeslot used for control messages, but not to trasmit data

Centralized Scheduling

Network manager decide the communication scheduling in a centralized way

  • To calculate the optimal one, it needs to collect informations of the network topology, traffic requirements of different nodes → collected by the path computation element (PCE)
  • can have some requirements, like no collision, maximum delay requirements, …

AMUS - Adaptive Multi-hop Scheduling

  • collision free and interference free
  • energy efficient
  • optimal resource allocation based on topology and traffic demand

Based on tentative cells → virtual resources assigned to improve reliability and achive ultra-low latency, by retrasmitting the packet

  • no deterministic bounds are provided

Schedule can be changed → dynamic

  • collision since the ratio of node one (one radio), can be syntonized to one single frequency → collision of the two pakets
  • interference since 2 and 3 are near each other
  • schedule is correct (number of slots reserved per requirements)
  • It’s not efficient since msg from node 4 needs to pass to node 2, but will be performed in the new time slot

How to calculate the topology?

  1. define traffic matrix (for each node, specify the data rate)
  1. extend it to the multipath traffic matrix (consider the entire path, not just the sender)
    • more 3-1 path since there is the one between 5-1 and the one 3-1

  1. Apply scheduling rules to each of the column in the MSS
    • how many slots to assign
  • We can use only two channel offsets to accomodate all the network requirements
  • Unused slots can be used to retrasmit msg (tentative cell)
    • Different policies to assign them → like proportional to the number of packets trasmitted
    • The receiver may wake up for the tentative cell → consume more energy
      • Every time a trasmitter sends the last packet in the queue, will send a notification since there will not be any other packet (receiver can sleep for the entire slot frame)

Optimal for:

  1. static topology and stationary traffic pattern
  1. optimal communication schedule
  1. low latency and high reliability (but not deterministic bouds, best effort algorithm)

Not Optimal for:

  1. Dynamic networks (eg some nodes fails or traffic change for external meteorology) → the communication schedule must be recomputed frequently and also trasmitted
  1. Large Networks → really complex algorithm that may not converge → not finding the schedule wanted (cannot implement divide and conquer approach)

In these cases we will use decentralized scheduling

Decentralized Scheduling

  • schedule computed based on partial informations, the founded schedule will typically be non optimal
  • Limited overhead → suitable for energy-constrained nodes

1) Cooperative Scheduling

  1. Demand estimation of packets requirement via a Scheduling Function (SF)
    • Can be domain specific or the default one (MSF)
  1. Negotiate the assignment of those slots → 6P

MSF Algorithm (Minimal Scheduling Function)

  • autonomous scheduled cells are used to transmit control messages, such as 6P messages for the negotiation of cells
  • Negotiated cells with 6Top Protocol
  • MSF periodically (every NUM_MAX_CELLS) checks the utilization of the node
  • not very reactive since one by one modification is not fast (good just for almost stationary rates)

On the Fly Reservation (OTF)

  • only negotiated cells
  • everything is based on the estimation (not just one cell at the time)

→ Performance Evaluation

Overprovisioning → allocating more cells to a node than what it’s necessary

  • This can help avoid frequent cell allocation and deallocation, thereby reducing the number of 6P transactions
  • However, this approach consumes more bandwidth due to the increased number of allocated cells, and more importantly, it can lead to failures due to a lack of resources
    • nodes that asks more cells will get a failure

Experiment setup: 5 replicas that will generate messages with different data rates

6LowPan mean transactions number for a specific SF and a specific data rate

  • needs to keep it low to reduce negotiation overhead and improve system performance

MSF have an higher failure rate than OTF

  • Lack of resources (especially at high rates), due to overprovisioning (more cells than needed, maybe when one node drops the packet needed) and Buffer Overflow at MAC layer (packets pile up waiting for cells, until the queue is full)
  • Anyway even OTF fails, especially at high traffic rates. Indeed, we observed that when transitioning from T=2 to T=6, many negotiations fail due to overprovisioning
  • Not neglegible (sometime higher then 50%) → depends strongly on SF and parameters setting

The transaction delay, measures the time interval between the transmission of a request and the reception of the corresponding successful response

6P Transaction Delay in the order of seconds → not neglegible

Limits of distributed scheduling are:

  1. 6P transactions experience an avg. delay in the order of seconds
  1. A significant % of 6P transaction fail
  1. 6P negotiations increases the network overhead
  1. 6P transactions are prone to attacks
    1. Traffic Dispersion Attack → Destroy 6P message destined to a victim node
    1. Overloading Attack →Allocation of unnecessary cells, increasing the energy consumption of the victim node

2) Autonomous Scheduling

In autonomous scheduling, the communication schedule is computed locally and cooperatively by the nodes.

  • 6P protocol is no longer used for cell allocation → overcome its problems
    • no additional delay or network overhead introduced by 6P transactions and no 6P security attacks
  • In autonomous scheduling, nodes independently calculate the number of cells to allocate based on their own criteria
  • They also autonomously allocate these cells using a pre-defined hash function that is computed based on the node's address
    • computing the corresponding timeslot and channel offset using the hash function

How to allocate cells autonomously?

  • Node based approach: Receiver-based approach, Sender-based approach
  • Link-based approach

Receiver based approach: with respect to this example, the node will allocate one single cell to receive packet from all other nodes.

  • In addition to this, allocate also one cell to transmit for each of all its neighbor.
  • Both node, C and D, should use the same cell to transmit to B → collisions

Sender based approach: is the opposite. One cell is allocated for sending to any of the neighboring nodes, and one cell is allocated for receiving from each individual neighbor

  • no collision occurs
  • more energy usage since more Rx cells

Link based approach (ALICE) → the number of allocated cells is determined by the number of links (number of neighbor nodes)

  • For each link allocate a cell for Rx and one for Tx → Higher number of cells allocated then the prev approches

Note that:

  1. Fixed Allocation
    • The number of allocated slots per slotframe is fixed in all the considered schemes
      • It’s not dynamic and based on packet generation rate
    • A longer slotframe implies lower bandwidth allocation (since the number of slots will be the same) but better energy efficiency (can be for more time shutdown)
  1. Receiver-based performs worse than sender-based, but typically consumes more energy
    • A single Rx slot for all neighbors → collisions
  1. ALICE performs better than sender-based
    • Due to its link-based allocation, instead of node-based allocation → more slots per slotframe are allocated to the same node
    • more energy consumptions since the radio need to stay awake for more Rx cells
  1. Cell rescheduling in ALICE
    • Performed at each slotframe in ALICE to avoid conflicts that comes from collisions of the hash function
    • However, it has been observed that this rescheduling has no significant average-case effect. It may only have a significant impact in worst-case situations, and therefore rescheduling is typically not used in practice

Frame Pending (FP) bit in ALICE

  • Flag in the Frame Control Field of the TSCH frame
  • When set, the FP bit indicates that the recipient should remain active in the next timeslot and on the same channel, unless the next cell is already allocated for other purposes
  • no msgs overhead (FP bit is piggybacked to a message) and no security attacks

ALICE with Frame Pending bit is a simple mechanism to make ALICE adaptive. It’s a mechanism provided by the underling TSCH access protocol

Performance Comparison

Metrics used:

  1. Packet Delivery Ratio (PDR)
  1. End-to-end Latency, definedas the time interval between the generation of a data packet at the source node and its correct reception at the final destination
  1. Duty Cycle → ration between number of cells a node stay active over the slotframe length
    • indirect measure of energy consumption

Many-to-One communication → upward traffic from sensor to root

Periodic Traffic

Typical of monitoring applications

When the number of nodes grows up → PDR tends to decrease

  • However, this decrease is very remarkable with ALICE, while negligible for the others
  • since ALICE is fixed and the others are dynamic

With Frame Pending, the situation improve since also ALICE can adapt to network variations

  • The cost to pay for the better performance of E-OTF and
    MSF, with respect to ALICE, is the higher duty cycle
  • E-OTF typically has a larger duty-cycle than MSF because it allocates more cells

Burst Traffic

Typical of event driven applications

A lot msgs in a short period of time, then idle

Conclusions

ALICE is the optimal choice with moderate workload

  • no negotiation overhead
  • lower duty cycle → longer lifetime
  • moderate adaptation with FP bit

E-OTF and MSF is mandatory with high workload

  • dynamic cell allocations ensure better traffic peaks handling
  • the cost is an increased duty cycle

E-OTF outperforms MSF with bursty traffic and very dynamic networks

  • it adapts more rapidly to changes

Cloud-to-Things Continuum

Fog Nodes (FNs):

  • Located between cloud and edge, forming an intermediate computing layer
  • Aggregate data from multiple edge devices
  • Provide more computing power and storage than edge nodes
  • Handle preprocessing, filtering, and initial analytics
  • Reduce latency compared to cloud processing
  • Typically fixed infrastructure with stable power and network connections

Edge Nodes (ENs):

  • Directly interface with sensors, actuators, and end devices
  • Lower computational power but faster response time
  • Operate under constrained resources (power, storage, processing)
  • Often connected wirelessly to end devices
