IPv6

IPv4 addresses are not sufficient

  • from 32bit to 128bit

6LowPAN → try to compress the overhead of IPv6 protocol

  • The transport layer over IPv6 is UDP

Main Functionalities of IPv6:

  1. Larger Adress Space
  1. Auto-Configuration of addresses to nodes
  1. Header Changes
    • IPv6 simplifies packet headers by eliminating or shifting fields into extension headers.
    • The base packet is always 40 bytes, fixed in size → more efficient for routers
  1. Auth, Privacy and Security

Header Changes

  • No header checksum, since it’s provided also at the upper layer
  • Fragmentation performed only by the sending host, not by routers → reduced forwarding time at routers
  • Optional fields removed
  • If we want to add extra information → extended headers using daisy chain
  • New field for QoS support (priority field)

Header of 40 bytes vs. an average of 20 bytes for IPv4

  • could be an issue for constrained devices

No checksum on IPv6 datagram

  • checksum mandatory for TCP and UDP in IPv6
  • For UDP was optional over IPv4

Extended Headers

Extended headers follow the fixed header (the standard header of IPv6) and precede the transport header.

Fragmentation

The Maximum trasmission unit (MTU) is 1280 byte in IPv6 → if above fragmentation

  • in LLNs (IEEE 802.15.4) is 127 bytes

Path Maximum Trasmission Unit Discovery (PMTUD)

  • Used to discover the minimum MTU along the path (to avoid to fragment at a certain router)
  • Periodic discovery based on ICMP messages
  • Discovered MTU is cached for each destination
  • Implementations that do no implement PMTU have a default value of 1280 bytes

Whenever its size exceeds the minimum MTU in the path

  • The Fragment extension header carries the information necessary to reassemble the original datagram
  • Identification value assigned by the source node
  • Frag. Offset indicates the offset wrt the start of original packet
  • M: More Fragment (1) or Last Fragment (0)

IPv6 Adressing Scheme

  1. Unicast Adress → uniquely identify a single network interface
  1. Anycast Adress → indentify a group of interfaces
    • the datagram is set to just one of the member, typically the nearest host
    • Syntatically indistinguishable from a unicast address
  1. Multicast Adress → group of hosts (the datagram is sended to all the interfaces)
    • all-nodes address: FF02::1
    • all-routers address: FF02::2
    • Solicited-node adress: FF02:0:0:0:0:1:FFXX:XXXX
      • It’s calculated based on the least 24 significant bits of the node B unicast/anycast adress
      • Used for MAC discovery of node B from node A, in this way just B will listend to this request
      • Also used for DAD

IPv6 Notations

2020:0db8:0000:0000:0000:ff00:0042:0826

  • one or more leading zeros, from any group, can be removed 2020:db8:0:0:0:ff00:42:826
  • Consecutive sections of zeros are replaced with a double colon (::) → only one on the adress can be used 2020:db8::ff00:42:826

  1. Loopback Adress 0000:0000:0000:0000:0000:0000:0000:0001 , that can be abbreviated with ::1 following the second rule
  1. Unspecified Adress 0000:0000:0000:0000:0000:0000:0000:0000 , that becomes ::
    • Used as source address by a node that has not yet learned its own unicast address
    • Cannot be used as destination address
  1. Prefix identifies the subnet the interface belongs to
  1. Interface ID identifies the specific interface inside the subnet

Three typs of unicast addresses:

  1. Unique Local Adress (ULA) → intended for local communication (similar to IPv4 private adress)
    • internally routable
  1. Link-Local Adress → uniquely identify the host within the link, it’s not routable (point-to-point)
    • Used on a single link for auto-configuration, neighbor discovery, or in the absence of a router
    • Cannot be announced outside of the local link, or to reach outside destinations
    • The Interface ID is assigned by the node itself
      • Without the presence of a DHCP server, was originally derived from the MAC address of the NIC [network interface card] (security problems and changes when the NIC is changed)
      • Now MAC-based methods are replaced with hash-based method
  1. Global Adresses → uniquely identifies the host within the Internet
    • Must have the 3 left most bits set to 001
    • IPv6 addresses with embedded IPv4 addresses starts with 000
    • In most cases 64-bit prefix + 64-bit Interface Identifier
    • Hierarchically-structured
      • Subnet ID is an identifier of a link within the site

Neighbor Discovery Protocol (NDP)

Provides a set of key autoconfiguration features

  1. Presence of neighbors on a link
  1. Discovery of a router that provides network prefix
  1. Discovery of link-layer additional addresses
  1. Maintenance of reachability
  1. Find parameters along the network (MTU, hop limits, …)
  1. Adress autoconfiguration (computation of the unique IP global adress), adress resolution
  1. Next-hop determination for packet forwarding
  1. Neighbor Unreachability Detection (NUD) in the link
  1. Duplicate Address Detection (DAD)
  1. Packet Redirection to find a better next-hop route for a certain destination

In order to implement these services, 5 different ICMPv6 [Internet Control Message Protocol] packet types have been introduced:

  1. Router Solicitation, RS: used to trigger the sending of a RA message upon receiving
  1. Router Advertisement, RA: used by router to advertise its presence (it can be send periodically or in response to RS message). It can carry also parameters like prefix, DNS, default gateway address
  1. Neighbor Solicitation, NS: use in NUD and DAD and for asking address resolution (to get MAC from IP)
  1. Neighbor Advertisement, NA → the MAC requested
  1. Redirect → sent by routers to inform a host of a better first-hop router on the path to destination

IPv6 Auto-Configuration

AutoConfiguration is extremely important in IoT environments

  • very large number of nodes → no need for DHCP server

Two type of configuration: stateless and stateful

Stateless Local Adress autoconfiguration

It starts with FE80 (10 bits), followed by 54 bits equal to 0. The second part (64 bit), is generated starting from the MAC address and using a well known address hash algorithm

  • The Duplicate Address Detection (DAD) process will be invoked, to understand if my adress is unique

Stateless Address Auto-configuration (SLAAC)

No DHCP

  • Note that in the DAD process, a Solicited node multicast addresses is used.
  • The IP address of the sender is set to "unspecified" because the node cannot use the global address it just generated. This is because it is not yet certain if the address is available or in use by another node
  • It could wait the periodic RA or trigger one by sending the RS message

Stateless DHCPv6

Centralized mechanism, to prefer in complex networks, that provides

  • Network addresses
  • Other useful information (DNS server addresses, domain names, and other settings)
  • The requesting host uses the well-known link-layer address FF02::1:2 to address all DHCP servers, instead of the broadcast address

Once the IPv6 global address has been obtained (through stateless autoconfiguration, via RA), provides additional information

  • DNS name servers
  • SIP servers

Does not support address assignment

  • just provides configuration information
  • Simplicity is very appealing for LLNs

Stateful DHCPv6

  • GUA = Global Unicast Address
  • Default gateway = router’s link-local address obtained from RA

The host obtains from RA the default gateway and the IPv6 of the DHCPv6 server: it must contact it to obtain the GUA, DNS server address and other useful information.
