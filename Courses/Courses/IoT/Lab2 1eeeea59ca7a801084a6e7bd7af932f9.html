uIP in Contiki-NG

uIP is a minimal TCP/IP stack designed for very constrained devices, such as those used in IoT. It's known as "the world’s smallest IP stack." Because of limited memory, the entire stack shares a single packet buffer.

Data Flow: Transmission and Reception

Sending Data

  1. The application or upper layer writes data to the global buffer uip_buf.
  1. uIP adds the appropriate IPv6 headers.
  1. 6LoWPAN compresses these headers.
  1. The compressed packet is placed into the packetbuf, including metadata.
  1. The MAC layer then handles actual transmission.

Receiving Data

  1. The MAC layer receives the packet and writes it into packetbuf.
  1. 6LoWPAN reads from packetbuf, decompresses headers, and reassembles the datagram into uip_buf.
  1. The uIP stack then processes the data.

✅ uip_buf (Global Buffer)

  • Shared memory area used by the uIP stack.
  • Used to hold entire IP datagrams during send/receive.
  • Access restricted to: uIP, 6LoWPAN, and layers above.
  • Cannot be accessed by MAC or physical layers.

✅ packetbuf (Global Buffer)

  • Used by 6LoWPAN to build link-layer frames.
  • Includes both payload and metadata (attributes defined in packetbuf.h).
  • Used for communication between 6LoWPAN and MAC layer.
  • Access restricted to: 6LoWPAN or lower layers.
  • Only accessible outside of interrupt context.

✅ queuebuf (Queue Buffer Abstraction)

  • Allows storing multiple packet copies simultaneously (unlike packetbuf, which is global).
  • Each queuebuf holds the same data structure as packetbuf.
  • No global pointer exists; each module must manage its own queuebuf references.
  • Access rules:
    • Only from 6LoWPAN or below.
    • Outside of interrupt context, unless locked (as done in TSCH).

⚙️ queuebuf Configuration

  • Automatically initialized when enabled.
  • Can be disabled by setting:
    #define QUEUEBUF_CONF_ENABLED 0
  • Max number of buffered packets can be set via:
    #define QUEUEBUF_CONF_NUM <value>

Contiki-NG provides NullNet, a network layer that does nothing

  • with NullNet, network-layer packets are only created by the application, and sent as-is to the MAC layer

Different PAN ID to isolate from other sensors– ifyouare in a noisy environment, where you have other sensors that make interference or the channel is not good, you can change

  • IEEE802154_CONF_PANID
  • IEEE802154_CONF_DEFAULT_CHANNEL

/* Callback for all incoming NullNet packets */
static void
input_callback(const void *data,
               uint16_t len,
               const linkaddr_t *src,
               const linkaddr_t *dest)
{
  /* Copy payload into a local, null-terminated buffer */
  char received_data[strlen((char *)data) + 1];
  if(len == strlen((char *)data) + 1) {
    memcpy(&received_data, data, len);
    /* Log timestamp, payload, and source address */

    LOG_INFO_LLADDR(src);  // Print link-layer address :contentReference[oaicite:20]{index=20}
