6LowPAN Adaptation Layer

Enable the use of ipv6 in a constrained environment. Adds:

  1. fragmentation → when packet size is above the max threshold (127 bytes)
  1. header compression → reduce as much as possible the size of sent packets
  1. optimized neighbor discovery

Low data rate (250 Kbps) with star or mesh topologies

  • support for link-layer routing
  • support all types of adresses (short or long ip)

6LowPANs nodes

  1. host
  1. routers (6LR)
  1. Edge Routers (6LBR)

Route-Over and Mesh-Under

IP Link → nodes reachable withing a single IP hop

  • no single broadcast domain (since it would be costly)
    • broadcast domain → when nodes are reachable by the TX radio

Route-over instead of mesh-under

  • more complex but more interoperability

Mesh Under

The mesh networking functions are implemented at the data link layer

  • The mesh network appears to the outside as a single IP subnet (single prefix even though multiple routers)
  • The mesh network hides the complexity of the mesh from the IP layer, so from an IP perspective, all the mesh nodes appear to be on the same network link
  • The only IP router in such a system is the edge router

Simpler but introduce more difficulties later when adressing different devices

Packets

Maximum frame overhead: 25 bytes (127-25)

  • Frame control (2 bytes)
  • Sequence Number (1 byte)
  • Addresses (up to 20 bytes)
  • Frame Check Sequence (2 bytes)

MAC security header: 21 bytes (102-21)

  • AES-CCM-128 (21 bytes)
  • AES-CCM-64 (13 bytes)
  • AES-CCM-32 (9 bytes)

Payload (for IPv6 datagram): 48 bytes (81-48)

  • IPv6 header (40 bytes)
  • UDP header (8 bytes)

Payload (for Application Data): 33 bytes

Mesh Header

Is used with a mesh-under routing approach

  • Containes MAC addresses (in L2 the MAC address will contain the adress for the next hop router, not the final destination)
  • In L3 forwarding at each router I need to change the L2 Header with the new MAC

Fragment Header

Fragmentation is performed whenever the IPv6 exceeds the IEEE 802.15.4 MTU

Datagram_tag uniquely identify the fragmented frame, along with

  1. IEEE 802.15.4 source address (originator if a mesh header is present)
  1. IEEE 802.15.4 destination address (final destination if a mesh header is present)
  1. Datagram size

A reassembly timer is started when receiving the first link fragment

  • Upon the expiration of the reassembly timer, if not all link fragments have been received, all fragments must be discarded
  • fragmentation adds an overhead → should be avoided (energy, badwidth)

IPv6 Header Compression

Much of the information that is sent in sequences of network headers is redundant

Stateful Header Compression

  • Uses flow-based compression, meaning it relies on shared context or a "state" between sender and receiver to compress headers
  • Not ideal for LowPANs, as these networks often have short-lived flows or sessions, making it difficult to maintain that shared context

Stateless Header Compression

  • Avoids redundancy across layers without needing any prior context or state.
  • Works well for link-local addresses (addresses used for communication on the same local network link)
    • Examples include Neighbor Discovery (ND) and DHCP
  • Has limited effectiveness for packets destined outside the LowPAN, as it can’t remove as much header information without shared context

Context-based header compression

  • exploits some shared context between source and destination

Compressed header fields in the same order as in the original uncompressed IPv6 header

  • Version Field (V) is elided
  • Payload Size (PL) is inferred from the 802.15.4 frame
  • Traffic Class (T - 8 bits) + Flow Label (F - 20 bits) → TF (2 bits)
    TF BitsMeaning
    00No compression – Both TC and FL are sent fully in-line (32 bits).
    01Partial compression – TC is compressed to 2 bits (only ECN), FL is sent in-line.
    10TC is not compressed (full 8 bits), FL is elided (assumed to be 0).
    11Both TC and FL are compressed/elided (typically assumed defaults or inferred).
  • Next Header (NH 8 bit) → NH (1 bit)
    The Next Header field indicates the type of the next protocol header (e.g., TCP, UDP, ICMP)
    NH BitMeaning
    0Not compressed – Full 8-bit NH value is sent in-line.
    1Compressed – NH is elided, and its value is inferred (e.g., known from context or pre-agreed default like UDP or ICMP).
  • Hop Limit (HL 8 bit) → 2 bit Often predictable (64 or 255)
    HL BitsMeaningBits Sent
    00Hop limit in-line (full 8 bits)8 bits
    01Hop limit = 1, elided0 bits
    10Hop limit = 64, elided0 bits
    11Hop limit = 255, elided0 bits
  • Context Identifier extension (CID, 1 bit) added
    • Used when stateful compression is enabled. The 1-byte includes both SCI (4 bits) and DCI (4 bits)
    CID BitMeaning
    0No extra context info used
    11 byte of context information follows DAM
  • Source Adress Compression (SAC, 1 bit)
    SAC BitMode
    0Stateless compression
    1Stateful compression
  • Source Address Mode (SAM, 2 bits)

      SAM BitsMeaningBits Sent

Neighbor Discovery

Standard IPv6 doesn’t work well for lowPANs

  • multiple overlapping broadcast domains → how to discover?
  • Multicast communication within the LoWPAN is too expensive

It should

  1. minimize the messaging
  1. Disseminate context information to hosts as needed by 6LoWPAN header compression
  1. Disseminate context information and prefix information from the border router to all routers in a 6LoWPAN
  1. Provide a multi-hop Duplicate Address Detection mechanism suitable for route-over 6LoWPANs
  1. Provide support for sleeping hosts

Prefix Dissemination

  • All link-local addresses within the LoWPAN must be unique across the entire LoWPAN
  • done by RPL via RAs packets

Router Advertisement (RA) packets are sent periodically by IPv6 routers to announce their presence and provide important network information to IPv6 hosts

  • Used to automatically disseminate router information across multiple hops → the prefix

Registration

In standard IPv6 when a device configures its IPv6 address, it sends a Neighbor Solicitation (NS) message to check if anyone else is using that address

  • costly in LowPAN
  • Instead of letting each node perform DAD (Duplicate Address Detection) itself, Edge Routers (ERs) manage addresses centrally

Nodes must register with the edge node and periodically refresh their registration

  • nodes can be reached by the ER by direct radio link
  • Node Registration - Node Confermation

Nodes Responsabilities

Edge Router

Has both a 6LoWPAN interface and a regular IPv6 interface

  • Diffusing RAs to the 6LoWPAN network
  • Maintaining a whiteboard of IPv6 addresses
  • Duplicate Address Detection for the addresses it defends
  • Listening for RS and Node Registration messages

It forwards packets:

  1. from one 6LoWPAN to another 6LoWPAN or to the backbone network (uncompress the headers)
  1. from the backbone network to one 6LoWPAN
    • compress headers

LowPAN Hosts (Nodes)

  • Are required to do very little ND signaling (Neighbor Discovery), periodically renew their registration to one or more edge routers

Do not need to perform:

  1. DAD
  1. Adress Resolution (from MAC to IP) → already knows from the IP
  1. Neighbor Solicitation

  • After bootstrap, forms an optimistic IPv6 link local address from the EUI64 bit MAC address
  • sends a RS to its own link router (or BR)
  • Registers with the BR
  • The node should configure a global IPv6 address to communicate with nodes outside the 6LoWPAN networks.
