Operating Systems (OS) for constrained devices are designed to manage hardware resources efficiently, ensuring optimal performance

  • modularity
  • RealTime operation

It menages drivers, connectivity and power menagement

Contiki-NG: open-source Operating System for resource-constrained devices in the IoT

  • low poer IPv6 communication
  • code footprint is 100kB, and memory usage 10kB

Programmed in C

Uses events and callbacks to manage tasks, minimizing idle CPU usage → Event Driven Kernel

  • it’s not a thread based kernel (more complex synch management, like semaphore and consume more resources)

Protothreads → lightweight, stackless threading library for managing multiple tasks without the
overhead of traditional threading

  • share the same stack → no context switch overhead
  • only one protothread per time can be in execution

Processes are built on top of a lightweight threading library called Protothreads

 #include "contiki.h"  /* Main include file for OS-specific modules. */
 #include <stdio.h> /* For printf() */
 /* Declare and auto-start this file's process */
 PROCESS(hello_world_process, "Hello world process");
 AUTOSTART_PROCESSES(&hello_world_process);  // autostart at system boot


 PROCESS_THREAD(hello_world_process, ev, data){ // values of incoming events
	 static struct etimer timer;
	 PROCESS_BEGIN();  // no code above this, only var initialization
	 /* Setup a periodic timer that expires after 10 seconds. */
	 etimer_set(&timer, CLOCK_SECOND * 10);
	 while(1) {
		 printf("Hello, world\n");
		 /* Wait for the periodic timer to expire and then restart the timer. */
		 PROCESS_WAIT_EVENT_UNTIL(etimer_expired(&timer));
		 etimer_reset(&timer);
	 }
	 PROCESS_END();
 }
  • macros make the code more efficient by replacing function calls with direct code insertion,
    eliminating the overhead of a function call in time-critical cod
  • AUTOSTART_PROCESSES tells Contiki-NG the process that will be automatically started when the system boots up
    • could specify multiple threads
    • if not specified I need to call process_start()

The values local variables are not preserved protothreads across yields (leave up the execution to another protothread):

int i = 1;
PROCESS_YIELD();
printf("i=%d\n", i); // <- prints garbage, beacause the stack is shared among protothreads
										 // and it's not preserved

static int i = 1;
PROCESS_YIELD();
printf("i=%d\n", i); // <- prints 1

PROCESS_WAIT_EVENT_UNTIL() macro gives the control back to the scheduler that resumes the execution when an event is delivered

Contiki-NG processes are scheduled cooperatively (non-preemptive)

  • Cooperative scheduling means that each process running in the system is responsible for giving up control of the microprocessor or CPU voluntarily to allow other processes to run
  • Simpler then preventing → IoT, but risk to miss OS events, like UDP messagges

Processes run until they either

  1. finish their execution
  1. voluntarily yield control of the microprocessor or CPU to other processes
  1. wait for an event (I/O operation completion)

  • PROCESS_PAUSE() The scheduler will deliver any queued events, and then immediately schedule the paused process.
  • PROCESS_YIELD() The scheduler is not expected to schedule the paused process in the short term.
    • wait for an incoming event
    • can be polled by external process process_poll(&process_name)

A process can be started

  • by another process, through the process_start() function
  • automatically, through the AUTOSTART_PROCESSES()

PROCESS_EVENT_INIT and PROCESS_EVENT_EXIT are generated to the thread when another one creates it or kills it

Synch and Asynch Communication

 process_post(&process_B, PROCESS_EVENT_MSG, msg);
 process_poll(&process_B);
 process_post_synch(&process_B, PROCESS_EVENT_MSG, msg);

A poll is a specific type of high-priority, asynchronous event dispatched to a single receiving process or broadcasted

  • the kernel will schedule polled processes before, as well as in-between synchronous event dispatches
  • dispatched in a round robin fashion

Events posted synchronously, are immediately delivered to the receiving process. There is no event queue.

  • the posting process execution will stop until the receiving process has finished consuming the event, at which point the posting process resumes
  • cannot be broadcasted

Cooja

Coojaisa network simulation environment for Wireless Sensor Networks (WSNs) that is part of the Contiki-NG OS

  • simulates entire WSNs, where each node in the network can be individually programmed and monitored
  • allows developing and testing applications in scenarios where deploying a physical network might be impractical or expensive
  • supports simulation at different levels
    1. hardware (emulating the microcontroller)
    1. software (running the actual Contiki-NG OS and applications)
    1. network (simulating the radio communication between nodes)
