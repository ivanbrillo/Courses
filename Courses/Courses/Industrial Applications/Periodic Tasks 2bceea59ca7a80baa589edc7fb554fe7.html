Timeline scheduling

  1. Divide the hyperperiod (major cycle TTT﻿) into slots of equal lenght (minor cycle Δ\DeltaΔ﻿) → typically chosen as the Δ=mcd(C1,...,Cn)\Delta = \text{mcd}(C_1, ..., C_n)Δ=mcd(C1​,...,Cn​)﻿
    1. Δ≥max⁡Ci\Delta \ge \max C_iΔ≥maxCi​﻿ if we do not want to split the tasks
    1. T  ( mod   Δ)=0T \;(\bmod\; \Delta) = 0T(modΔ)=0﻿
  1. The tasks are statically allocated (before exec) in a slot for execution in order to respect the frequencies derived from the application requirements
  1. The execution in each slot is activated by a timer

Apriori feasibility check (Δ\DeltaΔ﻿ fix)

There is no context switches or preemption

Advantages:

  1. no RTOS required
  1. no context switches, thus low run-time overhead
  1. all tasks run with very low jitter

Disadvantages:

  1. The schedule must be computed by the programmer apriori
  1. It is difficult to expand/change the schedule, since a small change in the CiC_iCi​﻿ or worse on TiT_iTi​﻿ (may change the minor) might requires the compete redesign of the schedule

Sensitivity to Application Changes

  1. Increase computation time of a task
    • The schedule could become infeasible Ci+Cj>ΔC_i + C_j > \DeltaCi​+Cj​>Δ﻿
    • I could split a task in two, to be allocated in different time intervals
  1. Chenge in task frequency
    • Could lead to an update of TTT﻿ and Δ\DeltaΔ﻿, changing the whole schedule

  1. Execute tasks on a priority-based kernel → the programmer doesn’t need to specify the schedule

It works when Di=TiD_i = T_iDi​=Ti​﻿

  • set Pi≈1/TiP_i \approx 1/T_iPi​≈1/Ti​﻿ → in reality we want an integer, but is not important here, because we need only an order of priorities (if TA<TB<TCT_A < T_B < T_CTA​<TB​<TC​﻿ then PA>PB>PCP_A > P_B >P_CPA​>PB​>PC​﻿)

  • If a task set is not schedulable by RM, then it cannot be scheduled by any fixed priority assignment

  • EDF is implemented with a min heap where insertion and extraction is O(log⁡n)O(\log n)O(logn)﻿, I also need to recompute every time the priorities for each new job arrival

  • EDF can use the full processing power
  • EDF has a simpler schedulability check O(n)O(n)O(n)﻿ wrt O(n)O(n)O(n)﻿ for sufficient condition or pseudopolynomial for necessary and sufficient condition
  • EDF in average triggers lower number of context switches
