RT activities

A task is a sequence of instructions that in the absence of other activities is continuously executed by the processor until completion

  • In modern OS a task is within a thread (share the same address space)
  • computation time doesn’t consider suspension times

In a concurrent system, more tasks can be simultaneously active, but only one can be in execution (running)

  • A task that can potentially execute on the processor, independently on its actual availability, is called an active task. When in execution it is a running task
  • An active task that is not in execution is said to be ready → kept in the ready queue under a particular scheduling policy
    • The processor is assigned to the first task in the queue through a dispatching operation (loading context and start execution)
    • Operating systems that handle different types of tasks may have more than one ready queue

  • When tasks have different levels of criticality, preemption permits executing the most critical tasks, as soon as they arrive, reducing the response times of high priority tasks
  • tasks may be executed in disjointed interval of times

Task Constraints

Three task contraints: timing, precedence and resources

Timing contraints → activation, period, completion, jitter. They can be explicit or implicit:

  • Explicit → directly included in the system specification

Precedence contraints → they impose an ordering in the execution

  • Such precedence relations are usually described through a Directed Acyclic Graph (DAG), where tasks are represented by nodes and precedence relations by arrows
  • It introduces a partial order on the task set

Resource constraints → they enforce a synchronization in the access of mutually exclusive resources

  • A resource is any software structure that can be used by the process to advance its execution
    • data structures, sets of variables, a main memory area, a file, a piece of program, a set of registers of a peripheral device.
  • A resource dedicated to a particular process is said to be private resource
  • A resource that can be used by more process is called shared resource → some of them cannot be accessed together, thus mutual exclusion
    • A piece of code executed under mutual exclusion constraints is called a critical section

Two or more tasks have resource constraints when they share resources that are accessed through a synchronization mechanism

  • read the slide for the example

Mutual exclusion is implemented by two primitives, wait(s) and signal(s), that use a system variable s, called semaphore

For a binary semaphore, s=1s = 1s=1﻿ → free resource, s=0s = 0s=0﻿ → busy (locked) resource.

  • wait(s):
    • if s == 0, the task is blocked on a queue of the semaphore. The queue management policy depends on the OS (usually it is FIFO or priority-based in RT applications)
    • else set s = 0
  • signal(s):
    • If there are blocked tasks, the first in the queue is awaken (s remains 0), else set s = 1.

  1. When a running task executes a wait primitive on a locked semaphore, it enters a waiting state (blocked state), until another task executes a signal primitive that unlocks the semaphore.
  1. When a task leaves the waiting state, it does not go in the running state, but in the ready state, so that the CPU can be assigned to the highest-priority task by the scheduling algorithm

A semaphore initialized to 0 can be used to wait for an event generated by another task → Syncronization

The real problem occurs when a process L, whose priority is between D and W, enters the ready queue while W is executing the critical section.

  • Because of preemption, L starts running immediately.

Here is what happens:

  • D is blocked because it is waiting for W (via WAIT) to exit the critical section.
  • W is blocked indirectly because now L, which has a higher priority than W, preempts it and takes the CPU.
  • Even though L legitimately has a higher priority than W, its execution further delays D, which actually has a higher priority than L.

This situation may lead to an unbounded delay for D, because L may continue to preempt W indefinitely.

  • This phenomenon is called Priority Inversion, and this is the real problem.

Scheduling Anomalies

Theorem (Graham, 1976): If a task set is scheduled on a multiprocessor with some priority assignment, a fixed number of processors, fixed execution times, and precedence constraints, then increasing the number of processors, reducing execution times, or weakening the precedence constraints can increase the schedule length

  • intuitive solutions do not always work

Anomalies using delay primitive

  • Timing anomalies can occur when tasks using shared resources explicitly suspend themselves through a delay(T) system call, that could lead to a delay longer than T (and missed deadlines)

A delay in a task may also increase the response time of other tasks even without sharing any resource → never use delay

Doubling the execution speed may cause deadlines miss
