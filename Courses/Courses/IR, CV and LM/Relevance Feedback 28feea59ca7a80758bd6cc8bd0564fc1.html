Relevance Feedback

  • Information need is not a prior, but is conditioned of a task that we want to accomplish

Information need can be categorised in different dimensions:

  1. number of document i want
  1. type of information needed
  1. type of task that led to the requirement of infos

A query can be a poor representation of the information need

  • Users may find it difficult to express the information need
  • Users are encouraged to enter short queries (by search engine interface and by the fact that long queries do not work)

Ambiguity: the same query string may represent different information needs

  • eg. searching Cooper, Windows, Apple, ….

Difficult to generate well-formulated queries without:

  1. Knowledge of collection → how terms are distributed, types of doc (e.g. physics books until 70’, before a term was even invented), …
  1. Retrieval environment → Term weighting, query language, retrieval strategy, etc

First query is a trial run

  • Practically used to retrieve few useful items from a collection, we learn from those relevant ones (like some important terms)
  • Then, modify the uery terms
  • Remember that IR is an iterative process
    • Explicit interaction:
      1. Relevance Feedback: user says relevant/non-relevant → maybe add the most frequent term in those documents could be added to the query, and reformulated automatically
        • maybe with different weights
      1. Query term suggestion
      1. Query suggestion (complete new related query)
  • The position of the mouse is correlated to where we are reading
  • How much time we spend in one web-page (we are actually reading it) → Google actually implemented the browser to record the time

Relevance Feedback

  • Moving a given query toward the relevant items and away from the non relevant ones

Usually both of the following occur using the feedback:

  1. Expand query with new terms
  1. Re-weight terms in query → usually positive weights for terms from relevant docs, sometimes negative from non-relevant docs

RF (relevance feedback) is most useful for increasing recall in situations where recall is important

  • Recall is the fraction of all relevant documents that your system actually retrieves, it increases since it moves closer to the relevant document centroid
  • Users can be expected to review results and to take time to iterate

Pseudo-Relevance Feedback

Use relevance feedback methods without explicit user input

  • Just assume the top mmm﻿ retrieved documents are relevant, and use them to reformulate the query → automatic Query Expansion (QE)
    • The terms are not re-weighted, but we should

This method can can suffer from one major flaw, query drift

  • Query drift occurs when the documents used for relevance feedback contain few or no relevant
  • QE is a variable technique: some queries will be improved, others will be harmed

For QE we could consider:

  1. top-ranked documents
  1. previous query reformulations of users (query logs)
  1. Thesauri
    • list of synonyms and semantically related words and phrases
    • typically weight less the added terms
    • It improve recall but could significantly decrease precision
      • e.g. “interest rate” → “interest rate fascinate evaluate”
