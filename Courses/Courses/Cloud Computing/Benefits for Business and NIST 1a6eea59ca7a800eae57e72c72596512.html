Benefits for Business and NIST

Conventional Computing Paradigm

Traditional computing solutions for the implementation of business services required design and deployment of a complete IT infrastructure in-house

  • This can be performed with a significant initial investment for hardware and personnel
  • This required to have the personnel to design and maintain all the aspects of the system, from the Operating System to Networking
  • This results in a fixed cost for personnel and hardware repairs

The system must scale to accommodate a growing demand quickly → new hardware

  • Business can shrink (but I already bougth the resourcces) → waste of resources

Cloud Computing Benefits

It allows to introduce dynamic scalability and reduce costs, both initial and operational

  • no fixed cost
  • minimal management responsibility
  • more reliable and available
  • covers different geographic area efficently

Different customers share the same infrastructure, resources are fully exploited (no dead periods)

  1. Large enterprises offload some of their activity to cloud systems to reduce fixed costs
  1. Small enterprises or startups can afford to translate their ideas into business without excessive front-up costs
  1. Companies that require sporadic very high performance computing (HPC) capabilities only for a very short amount of time → Pixar (rendering)

Disadvanteges

  1. Network cost: cloud computing requires constant network connectivity to access the service. This introduces an additional cost for network bandwidth.
  1. Network Bandwidth: Although the cost of network access can be affordable, network bandwidth can be limited.
    1. When considering huge data it could be a bottleneck
  1. Legal Issues: The storage location of cloud consumer’s data might be outside their country region.
  1. data security over unreliable network

NIST Model

Cloud computing standardization is limited, as the technology is still novel

  • Every cloud provider adopts its technological solution for its services
  • As any technology, we need at least a standard model for convenience of understanding

The NIST model defines the basic aspects and characteristics of cloud computing:

  1. Essential characteristics: the set of mandatory features that each cloud computing system must have
  1. Service Models: the set of different types of service that are provided to consumers
  1. Deployment Models: the set of different models for the deployment of the cloud infrastructure

It focuses on what composes the cloud infrastructure and not how it is implemented

  • It is general and neutral enough to cover all cloud implementations available in the market at the moment

Essential

5 essential characteristics:

  1. Broad Network Access → accessed from anywhere
  1. Rapid Elasticity → scale out or down as needed
  1. Measured Service
  1. On-Demand → resources allocated upon request, without user interaction (ask to start the VM to the administrator)
  1. Resource Pooling → group of resources assigned to users
    • multi-tenancy system

Actors

Based on the model, the actors involved are: Cloud Consumer, Cloud Provider, Cloud Auditor, Cloud Carrier and Cloud Broker

The Cloud Broker is a third party that interposes, in some cases, between the cloud provider and the cloud consumer, in order to negotiates the relationship

  • can benefit from reducing the costs, by requesting services from multiple providers at the same time

Deployment

Deployment of a cloud infrastructure can be arranged in several ways (depending on customer requirements)

  1. Public Clouds: most popular, where the cloud infrastructure is managed by an organization that sell the resources
    • one to many relations with conusmers
  1. Private Clouds: deployed and managed by a single organization for its internal use
    • the management could be on the hand of a trusted external company
    • typical for high sensitive data
  1. Community Clouds: allow access to serval organization of the same community
    • shared cost wrt private clouds
  1. Hybrid Cloud: combination of private or community cloud with public cloud
    • With hybrid clouds the consumer gets both low-cost computing and highly scalable resources and high level of control and privacy

Also the costs could change

Service Delivery Models

In the conventional computing model, you need to take care of :

  1. Creating a physical infrastructure with servers, storage and network
  1. Install and configure the operating systems on the servers
  1. Install on each server a middleware/runtimes software to develop applications/services
  1. Develop and deploy the service
  1. Manage/store the data

Delivery models differs each other on how the level of abstraction from the hardware infrastructure

  1. Infrastructure as a Service (IaaS): they still need to take care of all the components of the platform and the applications:
    • os, confugure runtime, deploy and manage the data
    • no need to control the physical infrastructure, they provide VM, vCPU, vHDD, …
    • most used delivery model (AWS, AZURE, ….)
    • storage as a service, that can be offerend even alone
  1. Platform as a Service (PaaS): all the aspects from the physical infrastructure, to the installation of the operating system and a middleware/runtime platforms are managed by the provider
    • consumer only takes care of programming the app and manage the data
    • The main drawback is the lack of flexibility: applications must be programmed using the APIs exposed by the system
    • For this reason, applications programmed for one cloud platform can be hardly ported on a different cloud
    • database as a service, that can be offered even alone
  1. Software as a Service (SaaS): In the Software as a Service mode the cloud provider delivers to consumers applications as a service
    • all aspects, form HW to SW are handled by the provider

Can be built on top of each other
