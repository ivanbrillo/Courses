MapReduce and Hadoop

MapReduce

It is a programming model. It’s based in Divide and Conquer (since it is big-data)

  • Static partitioning of the input data
  • N slaves are created dynamically
  • Each slave is assigned a partition of the input

This pattern doesn’t work well if the assigned task are unbalanced

Tackling large-data problems requires a new approach:

  1. Right level of abstraction → hide implementation details
    1. Drawbacks: evertything needs to fit into the abstraction
  1. Scale out, not up
    1. Higher probability of failures but cheaper
  1. Move processing to the data → drawback need portable code
    1. fixed location of data and deploy the task where the data is, not moving data

MapReduce inherits a lot of principle of functional programming

  1. Purity → will always produce the same output, given the same input parameters (idempotency). Deterministic Behaviour
  1. Immutability → no variables in functional programming, just constants
    1. A process does not need to bother about other processes when dealing with a data structure, as nobody can modify it
    1. History is not wiped out
  1. Higher-order functions → functions that operate on other functions (taking them as argument or spit it out as output)

Programmers specify two functions:

  1. map function: from [key, value] (1) to [key, value] (0*)
    • Produces as output a list of key-value pairs (typically 1 or more per input)
    • The function is invoked by the mapper (higher order function)
    • Mappers should run on nodes which hold their (portion of the) data locally, to avoid network traffic
    • Multiple mappers run in parallel, each processing (a portion of) the input data
    • Most of the time map tasks ignore the key
  1. reduce function: from [key, list of values] (1) to [key, value] (0*)
    • Produces as output a list of key-value pairs (typically none or 1 per input)
    • The function is invoked by the Reducer (function)

    Both are STATELESS

In Between Steps:

  • Intermediate values for a specific key, that are outputted by the map function, are combined into a list (shuffle) → Each of this given to a reducer. There may be a single reducer, or multiple reducers
    • All values associated with a particular intermediate key are guaranteed to go to the same reducer
    • The intermediate keys, and their value lists, are passed to the reducer in sorted key order → sort
    • Output is written to the distributed file system
  • Mapper takes the doc (entry, like a byte line of a document) and the offset of the entry in the overall document
Examples
  • I take the key of the first a “total”

Both functions are STATELESS (no state sharing between two invokations)

Partitioners

Partitioners balance the key assignments to reducers (in-between mapper and reducers)

  • By default, intermediate keys are hashed to reducers
  • Partitioner specifies the node to which an intermediate key-value pair must be copied
  • Partitions key space for parallel reduce operations
  • Partitioner only considers the key and ignores the value → same reducer (hash)

Combiners

Combiners does a local aggregation before the shuffle

  • is optional, not mandatory. It’s an optimizer

All the key-value pairs from mappers need to be copied across the network

  • The amount of intermediate data may be larger than the input collection itself
  • Perform local aggregation on the output of each mapper (same machine)
  • Typically, a combiner is a (local) copy of the reducer, a «mini-reducer» that takes place on the output of a specific mapper → same code
  • To use combiners, the reduce function must be associative and commutative → Otherwise I cannot use the combiner before reducer

Hadoop

A MapReduce job is a unit of work that the client wants to be performed. It consists of:

  1. Input data
  1. MapReduce program
  1. Configuration information

Hadoop runs the MapReduce job by dividing it into tasks (map and reduce tasks)

  • The tasks are scheduled using YARN (Yet Another Resource Negotiation) and run on nodes in the cluster.
  • If a task fails, it will be automatically rescheduled to run on a different node.
  • Hadoop divides the input to a MapReduce job into fixed-size pieces called Input Splits
  • Hadoop spawns one map task for each split, which runs the user-defined map function for each record in the split

Generally Hadoop can run in three modes:

  1. Local (or standalone) mode - this is the default
    • Hadoop runs as a single Java process
    • Mainly used for debugging
    • The jobs will run as if there is 1 mapper and 1 reducer
  1. Pseudo-distributed mode (also known as single-node cluster)
    • All the daemons run on a single machine
    • A separate JVM for every Hadoop component
    • This setting mimics the behaviour of a cluster
  1. Fully-distributed mode
    • This is how Hadoop runs on a real cluster
    • All the daemons run on (a subset of) the cluster's machines using the HDFS protocol

Word Count Example

public static class TokenizerMapper extends Mapper<Object, Text, Text, IntWritable>
{
	 private final static IntWritable one = new IntWritable(1); // value type
	 private Text word = new Text(); // key type
	 
	 // value -> input value (doc line), the key is the offset
	 // context includes configuration infos, in order to interact with hadoop (db, combiners, ...))
	 public void map(Object key, Text value, Context context) throws IOException, InterruptedException {
		 StringTokenizer itr = new StringTokenizer(value.toString());  // devide line into list of words, better then splits (also \n and more spaces)
		 while (itr.hasMoreTokens()) {
			 word.set(itr.nextToken());
			 context.write(word, one);
		 }
	 }
}
  • Text and IntWritable are not default types in Java, but are needed for serialization
public static class IntSumReducer extends Reducer<Text,IntWritable,Text,IntWritable> 
{
	 private IntWritable result = new IntWritable();
	 
	 public void reduce(Text key, Iterable<IntWritable> values, Context context) throws IOException, InterruptedException {  
		 int sum = 0;
		 for (IntWritable val : values) {
			 sum += val.get();
		 }
		 result.set(sum);
		 context.write(key, result);
	 }
 }
 public static void main(String[] args) throws Exception {
	 Configuration conf = new Configuration(); // exchange infos between mapper and reducer
	 String[] otherArgs = new GenericOptionsParser(conf, args).getRemainingArgs();  // analyze the input argumets provided by the command line
	 if (otherArgs.length < 2){ // one argument is the input data and the second where to store the output
		 System.err.println("Usage: wordcount <in> [<in>...] <out>");
		 System.exit(2);
	 }
	 
	 Job job = Job.getInstance(conf, "word count");
	 job.setJarByClass(WordCount.class); // map and reduce inside that archive (specify a class in that archive)
	 job.setMapperClass(TokenizerMapper.class);
	 job.setCombinerClass(IntSumReducer.class);  // same as reducer!
	 job.setReducerClass(IntSumReducer.class);
	 job.setOutputKeyClass(Text.class);
	 job.setOutputValueClass(IntWritable.class);
	 // the output type from map by default is the same as the reducer
	 
	 for (int i = 0; i < otherArgs.length - 1; ++i)
		 FileInputFormat.addInputPath(job, new Path(otherArgs[i])); // several inputs
	 
	 FileOutputFormat.setOutputPath(job, new Path(otherArgs[otherArgs.length - 1])); // only one directory, it will have one file for each reducer
	 // violates the immutability principle if I'm trying to overwrite it
	 
	 System.exit(job.waitForCompletion(true) ? 0 : 1);   // true is verbose
 }

Types

  • map function: from [key (K1), value (V1)] pair to list of [key (K2), value (V2)] pairs
  • combiner function: from [key (K2), list of values (V2)] pair to list of [key (K2), values (V2)] pairs
  • reduce function: from [key (K2), list of values (V2)] pair to list of [key (K3), values (V3)] pairs
  • partitioner function: from [key (K2), value (V2)] pair to integer (hash code of the key) → module with the number of reducers

Input types are set by the input format

If not set explicitly, the intermediate types default to the (final) output types, which default to LongWritable and Text

  • It is possible to configure an Hadoop job with incompatible types, because the configuration isn’t checked at compile time.

Serialization in Hadoop

Serialization is the process of turning objects into a byte stream. Deserialization is the reverse process of turning a byte stream back into a series of objects.

  • Serialization is used in two quite distinct areas of distributed data processing
    1. for interprocess communication → using RPC protocol
    1. for persistent storage
  • Hadoop uses its own serialization format called Writables
    • eg IntWritable

  • Compact (least overhead possible) and fast (in terms of serialization deserialization process) → I need it because custom data types
public interface Writable 
{
	 void write(DataOutput out) throws IOException;  // serialization
	 void readFields(DataInput in) throws IOException; // deserialization
} 

public interface WritableComparable<T> extends Writable, Comparable<T> 
{ }  // Comparable is built in in Java
// Comparable is needed eg. in the sorter

public class IntWritable implements WritableComparable {
 private int value;
 
 public IntWritable() {}
 public IntWritable(int value) { set(value); }
 
 public void set(int value) {  this.value = value; }
 public int get() {  return value;  }
 
 public void readFields(DataInput in) throws IOException {
	 value = in.readInt();
 }
 
 public void write(DataOutput out) throws IOException {
	 out.writeInt(value);
 }
 
	public boolean equals(Object o) {
	 if (!(o instanceof IntWritable))
		 return false;
	 IntWritable other = (IntWritable)o;
	 return this.value == other.value;
	}
	
	// for the paritioner, just the value because it's already an int
	public int hashCode() {  return value; }
	
	// used by the sorter
	public int compareTo(Object o) {
	 int thisValue = this.value;
	 int thatValue = ((IntWritable) o).value;
	 return (thisValue<thatValue ? -1 : (thisValue==thatValue ? 0 : 1));
	}
	 
	// Not for serialization -> output format is text (takes the 
	// output (key and value) of the reducer and convert it to String, 
	// separated by a tab)
	public String toString() {  return Integer.toString(value); }
}

Hadoop Input

Chunks → physical decomposition of the input

An input split is a logical split → just a reference to the data (doesn’t contain the data)

  • An input split is a portion of the input that is processed by a single map task
  • Each split is divided into records, and the map task processes each record – a key-value pair – in turn
  • In a database context, a split might correspond to a range of rows from a table, and a record to a row in that range
  • Input splits are represented by the class InputSplit
    • An InputSplit has a length in bytes and a set of storage locations (i.e., hostname strings)
  • The storage locations are used by Hadoop to place map tasks as close to the split’s data as possible
  • The size is used to order the splits so that the largest get processed first, to minimize the job runtime → maximize parallelization (try to finish at the same time)
public abstract class InputFormat<K, V>  {
	public abstract List<InputSplit> getSplits(JobContext context)
		 throws IOException, InterruptedException; 
		 // get the split based on the infos in the context
	
	public abstract RecordReader<K, V> createRecordReader(InputSplit split, TaskAttemptContext context) 
			throws IOException, InterruptedException;
			// invoked by the mapper task (not the one we implement)
			// the first thing it does is to call the method to get the records 
}

Splits for the job are created through the getSplits() method

  • Splits are then sent to the application master, which uses their storage locations to schedule map tasks that will process them on the cluster
  • The map task passes the split to the createRecordReader() method on InputFormat to obtain a RecordReader for that split.
  • A RecordReader is little more than an iterator over records, and the map task uses one to generate record key-value pairs, which it passes to the map method.

Setup and Clean-Up methods

It is common to want your Mapper or Reducer to execute some code before the map() or reduce() method is called for the first time → setup(context)

  • Initialize data structures
  • Read data from an external file
  • Set parameters

Similarly, you may wish to perform some action(s) after all the records have been processed by your Mapper or Reducer

  • The cleanup() method is called before the Mapper or Reducer terminates
  • free resources
