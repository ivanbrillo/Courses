Foundamental Concepts

Cloud Computing

  • it is the result of a series of developments that have taken place over the past few decades
  • only the composition of some key technologies has enabled cloud computing (virtualization …)

MainFrames

Commercial usage of computing started around 1970s with mainframes (large computer installed in a room)

  • Organizations acquired such hardware to automate basic data processing
  • So expensive a company couldn’t afford more than one → time-shared utilization
  • Different users were accessing the mainframe from terminals

PC Revolution

At the end of the 70s less expensive computers came into the market → Personal Computer

  • Big organizations installed multiple PCs in different offices
  • Network communication technologies were introduced to allow communication between PCs for data transfer (LAN and WAN)

This lead to the creation of distributed applications

Also introduced the parallel processing (more task computed together on the same PC)

Distributed Computing System

Applications are programmed to be executed in a distributed manner as a composition of different tasks

  • Nodes communicate to exchange data or results

Cluster Computing

The next natural step was the creation of clusters: groups of multiple nodes (computers) all connected to the same LAN to perform the same (or similar) tasks

  • Computers are clustered together for a more efficient computing (less communication overhead) and to improve reliability (if one fail the other take over)
  • Among the PCs of a cluster, one node is selected as cluster head → distribute the tasks

Grid Computing

  • The cluster head represented a single point of failure
  • To mitigate this risk in early 90s a new architecture was introduced, grid computing: a pool of resources in which the control functionalities were implemented in a decentralized manner (not in the cluster head) → masterless between nodes inside the grid

It had many drawbacks:

  • Real-time scaling was not possible: more computing power/storage → unlike modern cloud, grid computing did not have built-in mechanisms to efficiently scale on demand
  • The system was not fault tolerant: the failure of a node results in the failure of a task
    • No failure management system where developed (replication, redundancies)
  • Heterogeneous hardware required code adaptation → developers needs to write different codes for the different platflorms, no abstraction

Hardware Virtualization

The execution of software on different architecture without changes required to decouple software systems from the underlying physical resources of computers

  • This would allow to deal with hardware diversity but also to achieve real time scalability
  • a layer of software over the hardware system that could simulate the whole physical system environment and provide a common interface

Web Based Technologies

In addition to enabling grid computing to empower the development of large computing systems, faster networks allowed users from different geographical locations to collaborate in almost real time

Service Oriented Architecture (SOA)

It is a development method in which applications are developed by leveraging software components (services) interacting each other

  • Each service is an independent entity that communicate with the others via messages
  • Flexible to changes

Utility Computing Model

Computing era reached a point in which we had:

  1. Scalable computing infrastructure made of heterogeneous resources
  1. Distributed computing environments empowered by high bandwidth networks
  1. Collaborative environment across the world via web services
  1. Flexible applications via SOA

Utility Computing: delivering of computing resources as utility, following a pay per use model and on demand

  • Crucial enabler for this model was hardware virtualization
  • Eventually it become cloud computing

Cloud Computing

Historically the term ‘Cloud’ has been used as an abstraction of the network in system diagrams

  • In general, Cloud Computing refers to both the applications delivered as services over the internet and the infrastructure (hardware and software) in the datacenter that provides those services

Cloud Computing original definition: cloud computing is a distinct IT environment designed for the purpose of remotely providing, scalable and measured, IT resources that are accessible via the Internet

  • IT Resources → CPU, RAM, disk storage
  • IT envornment (infrastructure) must be connected to the internet
  • Without scalable and measured properties I have a remote server, not cloud
    • Scalable → made available upon request of user in a matter of short time
    • Measurable → the usage of those resources by the user must be measurable (eg. seconds of CPU, GB of storage, network bandwidth, …)

Cloud Service

Such resources provided by the Cloud Infrastructure are used to implement Cloud Services

A Cloud Service can be itself an application or offer a pure service.

  • When it implements an application, it usually exposes an interface that is accessed directly by users via web pages (using a browser)
  • When it implements a service that is exploited by other applications, it can be accessed via a set of programming interfaces API

Examples:

  1. Cloud file storage services (via pure service or application)
  1. Cloud ERP services (Enterprise Resource Planning)

XaaS (Everything as a Service)

variety of services and applications delivered to users over the internet, rather than being provided locally

  • advantages of cloud applications

Roles

Primary Roles:

  • Cloud Provider: The organization that provides cloud-based IT resources. It is usually responsible for creating and managing the Cloud Infrastructure. Normally IT resources are made available for lease by Cloud Consumers
  • Cloud Service Owner: The person or organization that create a cloud service running on the resources provided by the cloud infrastructure (pays the cloud provider)
  • Cloud Service User: The final user of a cloud service (pays cloud service owner to use their service)

Secondary roles:

  • Cloud Resource Administrator: The person or the organization responsible for administering cloud-based IT resources. The administrator usually belongs to the cloud provider, but it can belong also to the cloud consumer
    • Third party that reduce prices, like buying more resources from more providers
  • Cloud Carrier: The party responsible for providing connectivity between users and the cloud provider (between datacenter and internet)
  • Cloud Auditor: A third-party that conducts independent assessments of the cloud environment. Its role typically includes evaluating security and performance.
    • make sure contracts between provider and service owner are respected
  • Cloud Consumer: An organization (or a human) that has a formal contract or arrangement with the Cloud Provider to use IT resources → who actually use the resources
    • 99% are equal to service owner, but consumer may not create the service, but I could just buy from a company the application

Cloud Model

Since resources are measurable → It adopts a utility-based model

Since resources are scalable → resources can be provisioned dynamically upon request

  1. Utility Based Model: IT resources (computing, storage, connectivity) are delivered using a ‘pay-per-use’ price model
    • pay only what they use
  1. Dynamiclly provisioned resources: resources are managed with minimal effort, without the need for human intervention
    • allocated upon request in a short amount of time
    • Resources can be provisioned not only as per request of a human but also under the orchestration of a software that request more/less resources

Business Model

  • Cloud computing providers (e.g. Amazon, Rackspace, Google) sell IT resources
  • Other companies (the Cloud consumer) buy such resources to create services and applications they can use internally or sell to their customer

Cloud Computing Infrastructure

Cloud infrastructure is deployed in datacenters by the cloud provider

  • Datacenter: a dedicated space to house servers and network equipment

Such hardware provide IT resources such as computing, storage and networking

  • Eventually such resources are accessed by multiple cloud consumers at the same time via internet connection

Multi-Tenancy

The traditional computing architectures are multi-users system, thus allowing multiple users to access the resources of a system → NOT cloud computing

  • The system (e.g. a server) is installed and configured by an administrator
  • When the number of users (each one with its own requirements) increases, it becomes impossible for the administrator to handle all the requirements

Ideally, we would like to have a multi-tenant architecture in which multiple consumers are served at the same time

  • Tenants are not user, they are the administrators of their system, they can control all its aspects
  • The cloud computing infrastructure is multi-tenant, in order to be scalable we want cloud consumer to have the impression to be in control of the assigned resource

Virtualization

  • Virtualization is a key enabler to create a multi-tenant infrastructure → without is a multi-user system (otherwise everyone config will conflict)

Virtualization is a broad concept, it refers to every technique that allows to create a virtualized version of something (i.e. IT resources)

  • By using virtualization, multiple virtual copies of the real resources can be created
  • Cloud consumers have access not to the real versions but the virtualized ones, thus having the illusion that they are in complete control

The software that virtualize the resources measures their utilization

Hardware Virtualization

The most popular virtualization technology used in cloud computing is hardware virtualization that allows to create a virtual representation of all hardware resources of a physical machine (a server creating a virtual server)

  • Hardware virtualization or system level virtualization provides an abstract execution environment on top of which a full operating system can be run
  • It usually exploits different virtualization techniques to virtualize each component of the system
  • Each virtual environment on which an operating system is run is called Virtual Machine

Hardware Virtualization allows multiple Operating Systems to run on the same hardware

Different types, that differ on the level of abstraction (waste resources creating a more high level virtualization)

  1. Full virtualization
  1. Para virtualization
  1. Operating system virtualization

Hypervisor

The virtual hardware is managed and controlled by the virtualization layer

  • Core element of such layer is the Hypervisor or Virtual Machine manager, a software that recreates the virtualized hardware environment in which the guest operating system runs
  • The real machine on which the hypervisor runs is called host

Cloud Virtualized Infrastructure

  • In a datacenter, multiple servers are installed and interconnected
  • Each server runs a hypervisor for the execution of VMs
  • VMs can be created dynamically as cloud consumers require new resources to host new cloud services

All physical servers are interconnected though a high-speed local connection (LANs)

  • Through this network infrastructure each VM can communicate with external hosts (to expose its cloud services) or can communicate with other VMs (to implement complex services)

Horizontal Scaling

Allocating or releasing the same type of IT resources, e.g. the same type of Virtual Servers

  • Scaling out → new resources are allocated
  • Scaling down → resources are deallocated

  • For instance, new VMs are allocated running the same cloud service to handle more traffic
  • the most popular one

Vertical Scaling

When an existing IT resource is replaced by another with higher or lower capacity, or the configuration of the same resource is modified to have higher or lower capacity

  • Scaling up -> capacity is increased
  • Scaling down -> capacity is decreased

  • For instance, a VM is replaced/reconfigured to have 4 CPUs instead of 2 CPUs
  • less popular since some downtime is required during the switch
  • limited by the maximum capacity of the hardware
