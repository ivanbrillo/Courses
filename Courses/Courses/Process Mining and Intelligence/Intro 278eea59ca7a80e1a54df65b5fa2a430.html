Intro

We need another languange, since OOP isn’t sufficient to model the workflow of a business

Business Process: collection of activities, triggered by an event, achiving a specific discrete result for the customer or other stakeholders

  • activity is a piece of work, named as a single unit, but it could involve multiple actors making contributions
  • task is an actionable atomic item → decomposition of an activity
  • steps → compose a task
  • customer: recipient of the beneficiary of the result

A workflow is a (partial) automation of a business process. In a workflow resources, information, activities, follow a coordinated control flow established by a BP modeling language

  • Business Process (BP) Analysis includes a broad meaning encompassing modeling, simulation, diagnosis, verification, performance of BP
  • Business Process Modeling is the creative act of producing a workflow from a business process.

Imperative programming: tell the computer how to do things: a sequence of explicit commands that change program state

  • describes the step-by-step control flow
  • not good for BPMN

Declarative programming: tell the computer what you want, not how to get it

  • the execution engine figures out the steps to satisfy those constraints

BPMN (Business Process Model and Notation) is based in declarative paradigm (describe the external world, not the machine) since it provides:

  • human-readable: visual notation
  • accessible for various roles (managers and engineers)
  • machine-readable → serializable to XML for process execution

It is not a language for data flows → it’s more abstract

It’s not a notation to represent structures, functional decompositions, data models, organization strategies, business rules → other languages for that

When condition A happens, B may occur; the process must eventually achieve outcome C

They let the process engine decide: how to parellalize, which path, syncronizations, …

Petri ners are the assabler of BPMN (mathematical formal language)

  • I could also use UML, but it is not as readable as BPMN

  • Start event generates a token, meanwhile end event destroys it

Levels of abstraction:

  • level 0: least amount of detail, where the process is expended in subprocesses

At the level 0 process is a high-level and it is not executable → serves for documentation

  • level 1/2/3 will expand subprocesses in activities and tasks

  • Business Rule Task: a task meant to execute a decision or rule evaluation — i.e. it invokes a business-rule engine (or decision logic) with given inputs and returns outputs (decisions, computed values, etc.).
  • Script Task: a task in which a small script or piece of code is executed directly by the BPMN process engine (or runtime). It’s used for custom logic, simple computations or data manipulations.

Process delivers a specific, essential result

  1. Individual instances of the result are discrete and identifiable
    • Inspector was assigned [Joe is assegned or …]
  1. the result is countable in a time amount (e.g. how many I can get in an hour)
  1. The result is essential for the enterprise

Mushy verb sounds good but often say little about what was actually accomplished → DO NOT USE THEM

  • A Pool represents a participant in a business process. It can be a specific entity (e.g. department) or a role (e.g. assistant manager, doctor, student, vendor).

Orchestration and Choreography

When we need to coordiante different pools → typically by sending msgs

Orchestration: a process with central control of activities (like the control of an orchestra director), modeled as a private process, and containing optionally black box pools presenting external entities (other pools)

  • point of view: from one participant’s perspective

Collaboration (or orchestration) the ordered set of interactions between two or more participants as shown by pools, with their public processes and message flow between them.

  • No central control (distributed control)
  • Each individual participant reacts to events generated by the other participants (as in a choreographed dance where dancers react to behaviors of their peers).
  • It can contain optionally some orchestration or just black-box pools.
  • The processes within pools are abstracted to hide complexity or private information to partners

BPMN allows the explicit modeling of data transfer, via data objects, messages and data store.

  • Data objects only exist within a process, whereas data store represent persistent data.
  • UML class diagrams or technical terms diagrams could be used to refine data objects in process models → process view is integrated with data view.

Activity Markers in BPMN

Sub-Process Marker (+)

Indicates the activity contains a collapsed sub-process with its own internal workflow. Clicking or expanding it reveals the detailed process flow within.

Loop Marker (↻)

Shows the activity will repeat multiple times in sequence until a condition is met. Each iteration completes before the next begins (like a "while" or "for" loop).

Parallel Multi-Instance Marker (|||)

The activity executes multiple instances simultaneously in parallel. For example, reviewing documents by three people at the same time - all instances run concurrently.

Sequential Multi-Instance Marker (≡)

The activity executes multiple instances, but one after another in sequence. For example, getting three approvals where each must complete before the next begins.

Ad Hoc Marker (~)

Indicates activities within can be performed in any order, multiple times, or skipped entirely. The execution is flexible and non-predetermined, driven by performers' decisions rather than strict process flow.

Compensation Marker (◄◄)

Marks an activity that undoes or compensates for work already completed. Used for rollback scenarios when a process fails after partial completion (like refunding a payment if order fulfillment fails).
